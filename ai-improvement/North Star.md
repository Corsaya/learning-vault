# North Star

The one note that answers "what are we actually working toward, and why."
Read this at the start of any planning session; update it (with a Shifts
Log entry) when direction actually changes — don't silently overwrite.
Idea adapted from obsidian-mind's `brain/North Star.md`.

  direct frontier-API spend without a subscription workaround.
- A second-brain + assistant setup good enough that "build something even better
  in-house" is a real alternative to paying for frontier access. **The migration
  forced this early.**
- The "own model" ladder (use local → understand → fine-tune → train), staged in

## Anti-goals

- Don't over-engineer the vault with infrastructure sized for a company
  (44-command systems, semantic search indices) when a teenager's personal
  vault doesn't need it yet. Revisit only if the vault genuinely grows past
  what grep/Glob/Home.md navigation can handle.
- Don't let AI write in Donovan's voice anywhere creative (journal,
  agonizing-sentience prose) — organize, don't author.
- **Don't answer a failure of execution by building more plans.** The recurring
  pattern is that planning outruns doing (see the Japanese roadmap). If a system
  is built and unused, the fix is enforcement, not more system.
